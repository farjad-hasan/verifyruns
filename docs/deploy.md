# Deploying VerifyRuns for $0

Frontend on **Cloudflare Pages**, API on **Render** (free web service), database on **MongoDB Atlas M0**, time-based work driven by **cron-job.org**. Nothing here needs a card except Atlas (which doesn't charge on M0).

The API is stateless between requests (`serverless-ready`, 2026-08-28): the webhook runs the check inside the request, and heartbeats plus retries are drained by `POST /api/internal/tick`, which the scheduler calls. A host that sleeps between requests loses nothing.

## 1. MongoDB Atlas (M0)

1. Create a free cluster; add a database user; allow access from anywhere (`0.0.0.0/0` — Render's free tier has no fixed egress IP).
2. Copy the connection string; that is `MONGO_URL`. `DB_NAME` is `verifyruns`.

## 2. Render (the API)

1. New → **Blueprint** → connect `farjad-hasan/verifyruns`; Render reads `render.yaml` (service `verifyruns-api`, root `backend`, health check `/api/`).
2. Fill the secrets it asks for:
   - `MONGO_URL` from step 1
   - `FERNET_KEY` — generate once: `python3 -c "from cryptography.fernet import Fernet;print(Fernet.generate_key().decode())"` and **keep it safe**: losing it makes every stored connector secret unreadable
   - `PUBLIC_APP_URL` and `CORS_ORIGINS` — the Pages URL from step 3 (add it after step 3; redeploy)
   - `JWT_SECRET` and `VR_TICK_SECRET` are generated by the blueprint; copy `VR_TICK_SECRET` for step 4
3. Deploy. The API URL is `https://verifyruns-api.onrender.com` (or whatever Render names it).

**Free-tier behaviour:** the instance sleeps after ~15 minutes without requests and takes 30–50 s to wake. The cron ping in step 4 keeps it awake most of the time; the first webhook after a long idle may be slow, never lost. Optional email alerts: add `RESEND_API_KEY` and `ALERT_FROM`.

## 3. Cloudflare Pages (the frontend)

1. Workers & Pages → Create → Pages → connect the repo.
2. Build settings:
   - Root directory: `frontend`
   - Build command: `npm install --legacy-peer-deps && npm run build`
   - Output directory: `build`
   - Environment variable: `REACT_APP_BACKEND_URL` = the Render URL from step 2 (**no trailing slash**), plus `NODE_VERSION` = `20`
3. Deploy. `public/_redirects` (`/* /index.html 200`) makes deep links such as `/checks/<id>` and `/pricing` load the SPA instead of a 404.
4. Go back to Render and set `PUBLIC_APP_URL` / `CORS_ORIGINS` to the Pages URL (`https://<project>.pages.dev`, or your custom domain). Redeploy the API.

## 4. cron-job.org (ticks)

Create a job: `POST https://<render-url>/api/internal/tick`, every **5 minutes**, header `X-Tick-Secret: <VR_TICK_SECRET>`. Expect `{"heartbeats": 0, "retries": 0}` most of the time.

Anything that can send an HTTP request on a schedule works instead — a GitHub Actions workflow (`schedule: "*/5 * * * *"`, timing is best-effort), Google Cloud Scheduler, an n8n Schedule trigger.

Consequences of the tick interval: a missed heartbeat is noticed up to 5 minutes late; retry-before-alert fires ~30 s + up to 5 min after the fresh FAIL. Both are documented on the pages that mention them.

## 5. Check it

1. Sign up on the Pages URL; create a Check against `https://jsonplaceholder.typicode.com/todos` with minimum new records `0`; Run check now → PASS.
2. `curl -X POST https://<render-url>/api/hook/<secret>` → a JSON verdict in the response.
3. `curl -X POST https://<render-url>/api/internal/tick -H "X-Tick-Secret: …"` → counts.

## Not covered

- Custom domain on Pages (Cloudflare handles it; then update `PUBLIC_APP_URL`/`CORS_ORIGINS`).
- Backups: Atlas M0 has no automated backups — export periodically, and keep `FERNET_KEY` with the export.
- The n8n community node: point its Webhook URL at the Render URL; it needs nothing else.
